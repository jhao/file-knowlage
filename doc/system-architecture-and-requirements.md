# 高校档案知识化系统（前端现状）架构与需求整理

## 1. 项目目标（基于现有代码推断）
当前项目是一个 **React + TypeScript + Vite** 的单页应用（SPA）原型，面向高校档案场景，覆盖“上传 -> AI 解析 -> 人工校验 -> 归档检索 -> 权限管理 -> 系统配置”的业务闭环。

从现有功能看，系统核心目标包括：
- 支持多源档案（文档、图片、音视频、文件夹）上传与管理。
- 通过 AI 对档案进行元数据提取、知识实体识别与文本摘要。
- 通过人工校验保障归档质量与安全合规。
- 支持按角色（管理员/普通用户）控制可见菜单与关键操作能力。

---

## 2. 当前系统架构（前端视角）

## 2.1 技术栈
- 框架：React + TypeScript
- 构建工具：Vite
- UI：Tailwind 风格类名（组件内原子化样式）
- 图表：Recharts（仪表盘统计）
- 图标：lucide-react

## 2.2 应用结构
系统以 `App.tsx` 作为状态中枢，核心状态包含：
- 当前页面视图 `currentView`
- 档案数据集合 `documents`
- 当前角色 `userRole`
- 当前选中文档 `selectedDocumentId`

页面由左侧导航切换，主要功能模块：
1. **Dashboard（仪表盘）**：统计总量、待校验、处理中、归档量与趋势图。
2. **UploadZone（上传中心）**：支持上传文件/文件夹，上传后进入处理队列。
3. **VerificationView（智能校验）**：展示 AI 处理中或待审核文档，支持审批/驳回。
4. **ArchiveList（档案库）**：展示已归档文档列表。
5. **FileDetailView（档案详情）**：查看与编辑元数据、知识实体。
6. **MyUploadsView（我的上传）**：按时间查看当前用户上传记录。
7. **UserManagement（人员权限）**：查看用户角色与权限矩阵。
8. **SystemSettings（系统设置）**：实体类别等系统参数配置。

## 2.3 核心数据模型
`types.ts` 抽象出以下域对象：
- `ArchiveDocument`：档案主体（基础文件信息 + 状态 + 元数据 + 实体）。
- `ArchiveMetadata`：标题、类别、日期、作者、部门、摘要、关键词、安全级别、置信度等。
- `KnowledgeEntity`：实体名称、类型、上下文定位、置信度。
- `User` 与 `UserRole`：用户与权限能力。
- 关键枚举：
  - 状态：`UPLOADED / PROCESSING / 待人工校验 / 已归档 / 已驳回 / 待审批`
  - 类别：学籍、人事、科研、行政、会议纪要、多媒体、手稿、教材、新闻稿
  - 密级：公开、内部、机密、绝密

## 2.4 业务流程（前端模拟）
1. 用户上传文件，前端生成 `ArchiveDocument`，状态置为 `PROCESSING`。
2. 文件进入校验视图；AI 处理失败时置为 `待人工校验`。
3. 管理员在校验页对文档进行通过/驳回处理。
4. 已归档文档进入档案库列表；可在详情页进一步完善元数据与知识实体。

> 说明：当前代码主要使用前端内存态 + Mock 数据，AI 解析调用链在 `services/geminiService.ts` 中定义了系统提示词，但尚未形成完整后端任务流。

## 3. 需求分层（面向后续建设）

## 3.1 业务功能需求
- 档案上传与批量导入（含文件夹层级）。
- 自动解析（元数据抽取、文本提取、知识实体识别）。
- 人工审核与质量控制。
- 档案检索与详情查看。
- 个人上传记录追踪。
- 用户与角色权限管理。
- 系统参数配置（实体类型、策略等）。

## 3.2 非功能需求
- 安全：按密级与角色控制访问与操作。
- 可追溯：关键操作留痕（审批、修改、删除、导出）。
- 可扩展：支持多模型、多格式、多业务场景扩展。
- 高可用：异步任务可重试，失败可恢复。

## 3.3 集成需求
- 对象存储（原始文件、缩略图、解析中间件结果）。
- 数据库（业务主数据、配置、权限、审计日志）。
- AI 服务（OCR/ASR/LLM/NER）。
- 检索引擎（全文检索 + 结构化查询 + 向量检索，可选）。

## 4. 建议的目标系统架构（全栈）

## 4.1 分层架构
- **接入层**：Web 前端、统一 API 网关。
- **业务层**：档案服务、审核服务、用户权限服务、系统配置服务、检索服务。
- **AI 处理层**：文档解析、音视频转写、实体抽取、摘要分类。
- **任务编排层**：消息队列 + 异步任务 + 回调通知。
- **数据层**：关系型数据库 + 对象存储 + 检索索引 + 审计日志存储。

## 4.2 关键流程（建议）
1. 上传接口返回 `taskId`，文件入对象存储。
2. 任务编排触发解析流水线（OCR/ASR/LLM）。
3. 结果写入元数据表、实体表、全文索引。
4. 状态流转为“待人工校验”，推送给审核队列。
5. 审核通过后归档；驳回则进入整改状态。

## 4.3 权限与合规控制
- 基于 RBAC + 数据权限（部门/密级/归属人）。
- 针对导出、删除、密级变更启用审批流。
- 全链路审计：谁在何时对何对象做了何操作。

---

## 5. 里程碑建议
- **M1（后端打底）**：认证、文档 CRUD、上传存储、基础查询。
- **M2（AI 上线）**：异步解析流水线、状态回写、校验工作台对接。
- **M3（治理完善）**：权限细粒度、审计日志、审批流与告警。
- **M4（检索增强）**：全文/语义检索、多条件高级检索与导出。
